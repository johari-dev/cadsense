How many CAD renderers should stay alive?

This demo tests the renderer-pool model behind independent agent CAD sessions. Semantic viewer state must survive without owning a canvas; renderer-dependent captures are bounded, ordered per agent, and may be restored after suspension. The question is whether one or more invisible workers materially improve capture latency without making memory, GPU work, and desktop responsiveness scale with agent count.

Hypothesis under test: reserve one renderer for the visible CAD panel, start with one background worker, render only on commands or captures, release GPU geometry after a short warm idle, and grow to a second background worker only when measured capture latency stays inside budget and the device is not under pressure.
